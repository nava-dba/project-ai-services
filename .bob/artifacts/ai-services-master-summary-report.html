🎯 Project Goal & What Was Built

Add a standalone CLIP ViT-B/32 multimodal embedding service to the IBM AI Services Catalog, deployable on IBM Power (ppc64le) via Podman. The service exposes an OpenAI-compatible POST /v1/embeddings endpoint so Oracle 26ai on AIX can call it from PL/SQL via UTL_HTTP to generate 512-d vectors for VECTOR_DISTANCE() similarity search.

Stack

vLLM 0.19.1 · CLIP ViT-B/32 · IBM Power11 · Podman · Go embed.FS catalog · React Catalog UI

Deployment Paths

CLI (legacy): ai-services application create
UI: Catalog → Services → Deploy

Models Supported

openai/clip-vit-base-patch32 (512-d, multimodal)
ibm-granite/granite-embedding-278m-multilingual (768-d, text)

Oracle Integration

Text & image vectors via UTL_HTTP → stored in VECTOR columns → searched with VECTOR_DISTANCE() + HNSW index

🏗️ Critical Architecture Facts Discovered

The LPAR binary and the catalog backend container are completely separate. The LPAR binary handles bootstrap & CLI only. The backend container (ai-services:v0.0.223) has ALL templates baked in via //go:embed at build time. Fixing a template on disk has zero effect on UI deployments until a new image is built and deployed.
Correct rebuild order (most critical lesson): Edit source files → podman build → extract CLI binary from image → catalog uninstall → catalog configure. Doing these out of order was the source of several wasted build cycles.
Go embed.FS has no runtime override. Any YAML template change requires a full recompile + redeploy cycle. This is by design but creates a slow inner loop.

Metric vLLM ONNX Runtime Winner

Image embedding throughput 37.2 rec/s (1193.7s avg) 38.3 rec/s (1160.2s avg) ONNX +2.9%
Multimodal pipeline total 29.1 rec/s (1526.7s avg) 28.3 rec/s (1569.9s avg) vLLM +2.8%

⚠️ vLLM with default settings was 36% slower than ONNX. The 10% advantage only appears after three critical tuning changes: gpu_memory_utilization=0.3, batch=256, OMP_NUM_THREADS=28.

Strategic Routing Recommendation

  • Deploy vLLM as default pipeline for text search & RAG (+28.1% on text).
  • Route batch image-only indexing → ONNX Runtime for SLA-sensitive workloads (17× more consistent).
  • Future: INT8/FP16 quantization of CLIP vision encoder to address the 77% image-phase bottleneck.
